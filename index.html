CASE 01 · OPERATIONS PATTERN · CRM

Real-Estate CRM & Daily Calling Queues

Problem: Buyer/seller enquiries in spreadsheets and chat threads; missed follow-ups and no ownership. Observed in Bhubaneswar property operations.

Architecture: Intake → assignment → stage pipeline (New → Calling → Visit → Negotiation → Booked) → follow-up reminders → reporting. Role-based views for closers vs managers.

Implementation: Lead stages and SLA rules mapped first; calling queues and WhatsApp templates added incrementally; GST/billing fields kept separate from pipeline status.

Limitations: Requires team adoption and data hygiene; integrations scoped per client; no anonymised client screenshots shared.

CASE 02 · HANDS-ON BUILD · AUTOMATION

Playwright + n8n Lead-Intake Pipeline

Problem: Manual copy-paste of property listings into calling sheets; duplicates and missing fields.

Architecture: Python Playwright extractor → JSON normalizer (price, locality, contact, source URL) → n8n webhook → CRM queue with dedupe key.

Implementation: Sync Playwright scripts with explicit selectors; n8n validates payload, drops invalid rows, logs source; human reviews before bulk outreach.

PYTHONPLAYWRIGHTN8NWEBHOOKS

Verified result: Repeatable extraction-to-queue flow demonstrated on sample listings (technique validated, volume depends on source).

Limitations: Source-site layout changes need selector maintenance; rate limits and terms of sources must be respected.
